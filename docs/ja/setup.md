## 前提条件

- **Windows 10 (22H2) / 11** (x64 または ARM64)
- **BlueCaster 用の USB Bluetooth アダプター**: 別の USB ドングルをおすすめします。USB 接続の内蔵アダプターも使えますが、その場合は Windows 自身の Bluetooth が使えなくなります（[手順 2](#winusb) を参照）

BlueCaster がアダプターに WinUSB ドライバーを割り当てるので、[Zadig](https://zadig.akeo.ie/) はもう必要ありません（Zadig も引き続き使えます。[Zadig を使う場合](#zadig)を参照）。

## BlueCaster のインストール

[リリース](https://github.com/SeiyaFunaokaJP/BlueCaster/releases)はそれぞれ 2 つの形式で配布しています。中のファイルはどちらも同じです。

- **インストーラー版**（`BlueCaster-<バージョン>-win64-setup.exe`、ARM64 では `-arm64-setup.exe`）：管理者権限なしで現在のユーザーにインストールします。スタートメニューの項目（**BlueCaster**）とアンインストーラーを追加し、Microsoft Edge WebView2 ランタイムがなければ一緒にインストールします（Windows 11 には標準で入っています）。更新はアプリから入れられます（**設定 > 更新 > 今すぐ更新**）。プログラムは `%LOCALAPPDATA%\BlueCaster\` に入ります（3 つのプログラム、アンインストーラー、ライセンス文の入った `licenses\` フォルダー）
- **ポータブル版**（`BlueCaster-<バージョン>-win64-portable.zip`、ARM64 では `-arm64-portable.zip`）：好きな場所に展開して `bluecaster.exe` を実行します。3 つのプログラム（`bluecaster.exe`、`bluecaster-core.exe`、`bluecaster-driver.exe`）は同じフォルダーに置いたままにしてください。ポータブル版は更新を通知するだけです。WebView2 ランタイムが必要です

どちらの形式も設定、プロファイル、リンクキー、ファームウェアを `%APPDATA%\BlueCaster` に保存するので、互いに切り替えられます。アンインストールすると、**ユーザーデータを削除する** をオフにしない限り、このフォルダーも削除されます（サイレント アンインストールでは残ります）。

### v1 からの乗り換え {#from-v1}

v1 がインストールされた状態で v2 のインストーラーを実行してください。**インストール準備完了** ページに、先にアンインストールする以前のバージョン（v1 または 2.0.x）が表示されます。v1 が実行中ならインストーラーが終了を求め、v1 をアンインストールします。設定フォルダーは残るので、プロファイル、ヘッドホンのペアリング、ファームウェアのファイルは引き継がれ、ヘッドホンをペアリングし直す必要はありません。（Zadig で）WinUSB を割り当て済みのアダプターはそのまま使えます。**Windows 起動時に開始** がオンだった場合は、Windows の起動時に v2 が起動するようになります。

v2 は初回起動時に、v1 の設定を読み込む前に `%APPDATA%\BlueCaster\backup\v1\` にコピーします。

### 2.0.x（A2DP Windows Bridge）からの乗り換え {#from-2x}

BlueCaster 3.0.0 は A2DP Windows Bridge の新しい名前です。2.0.x がインストールされた状態で 3.0.0 のインストーラーを実行してください。セットアップが古いバージョンを自動でアンインストールし、設定は引き継がれます。スタートメニューの項目と **Windows 起動時に開始** の項目の名前は「BlueCaster」に変わります。

3.0.0 は初回起動時に、`%APPDATA%\A2DPWB` フォルダーの名前を `%APPDATA%\BlueCaster` に変え、中のファイルをサブフォルダーに整理します（[設定とファイル](architecture#settings-and-files)を参照）。`backup\v2\` には 2.0.x の設定とペアリングのコピーが残ります。2.0.2 に戻したいときは、これらのファイルを `%APPDATA%\A2DPWB` にコピーして戻してください。

ペアリングし直すまで、ヘッドホンには古い Bluetooth 名「A2DPWB」が表示されることがあります。

## 手順 1: 初回セットアップ {#first-run}

USB Bluetooth アダプターを挿して BlueCaster を起動します。初回起動時（オーディオデバイスがまだないか、WinUSB のアダプターがないとき）は、4 つの手順からなる **セットアップウィザード** が開きます。一度完了またはスキップすると、ウィザードは自動では開かなくなります。その後は **ホーム** または **オーディオデバイス** でデバイスを追加してください。

1. **アダプターを選ぶ**: 見つかった USB Bluetooth アダプターが一覧表示されます。お使いのアダプターがなければ、挿してから **再検出** を押します。BlueCaster で使えるかどうかは、緑の **対応** か赤の **非対応** で表示されます。非対応のアダプターは一覧に表示されますが、選べません
2. **ドライバーとファームウェア**: これから行う内容が一覧表示され、**このアダプターを準備** で実行します。BlueCaster はアダプターのドライバーを WinUSB に置き換え（Windows が管理者の許可を求めます。[手順 2](#winusb)を参照）、アダプターに必要な Realtek のファームウェアファイルをダウンロードします（[ファームウェア](#firmware)を参照）。BlueCaster がダウンロードできないファームウェアは、手動でファームウェアフォルダーにコピーしてください。このアダプター経由で Windows にペアリングされたデバイス（内蔵アダプターにつないだキーボードやマウスなど）がある場合は、ボタンを押すと先にその一覧が表示されます。BlueCaster がアダプターを使っている間、これらのデバイスは Windows で使えなくなります。**キャンセル** を選べば、そのまま使い続けられます。専用の USB レシーバーを使うデバイスは影響を受けません。ほかのデバイスも使い続けたいときは、BlueCaster には別の USB アダプターを使ってください。この一覧は **アダプター** 画面の **WinUSB ドライバーに置き換える** でも表示されます
3. **オーディオデバイスを探す**: 検索は自動で始まります。オーディオデバイスをペアリングモードにして、その横の **接続** を押します（アドレスを入力して **使う** を押しても構いません）。BlueCaster はそのデバイスが対応する最良のコーデック（自動）でデバイスを保存し、接続します。接続したデバイスは **ペアリング済みのデバイス** の下に状態を示す点付きで表示され、検索は止まります。**デバイスを追加** を押すとそのデバイスを切断し、別のデバイスを探すために検索を再開します。最初のデバイスは保存されたままで、間違えたデバイスはそこで削除できます。このアダプター経由で Windows がペアリングしたデバイスがあるときは、**Windows のペアリングを取り込む** が表示されます。その **取り込む** ボタンを押すと、すべてにチェックが入った状態でデバイスが一覧表示されます（[手順 3](#headphones)を参照）。**次へ** はデバイスがなくても押せます。オーディオデバイスはあとで **オーディオデバイス** 画面で追加できます。新しいデバイスは、**Hi-Fi Cable** がインストールされていればそれを、なければ VB-CABLE をキャプチャします。Hi-Fi Cable は遅延が最も少ないので再生音に、VB-CABLE はヘッドホンのマイクにおすすめします。ケーブルが足りないときは、この手順に警告が表示されます。警告の **詳細** には両方のケーブルが載っています。VB-CABLE の **インストール** は、VB-Audio の VB-CABLE パッケージ（1.3 MB）をダウンロードしてインストールします（管理者の確認が表示されます。表示されないときは Windows を再起動してください）。Hi-Fi Cable の **ダウンロード** は VB-Audio のページを開きます。インストール済みのケーブルには、代わりに **アンインストール** が表示されます。どちらのケーブルも VB-Audio のドネーションウェアです（[vb-cable.com](https://vb-cable.com/)。**このソフトについて** にも記載）。BlueCaster は VB-CABLE を同梱しておらず、寄付は VB-Audio に届きます。企業などの組織には、VB-Audio がインストールごとのライセンスを求めています（[ライセンス](https://vb-audio.com/Services/licensing.htm)）。あとで BlueCaster が初めてケーブルを見つけると、**既定のデバイス** に設定されたデバイスはそのケーブルのキャプチャに切り替わります（VB-CABLE の場合は、Hi-Fi Cable がインストールされていないときだけ）。マイクの出力先が使えないデバイスは、マイクの音をそのケーブルに送ります。コーデックはあとで **コーデック** 画面で変更できます
4. **全般設定**: テーマ、**起動**、**通知**、更新の確認です。設定画面と同じ項目で、変更はすぐに保存されます。初回のセットアップでは **Windows 起動時に開始** と **トレイに最小化して起動** がオンになります

**あとで設定する** を押すと、残りの手順をスキップします。**設定 > セットアップを実行** でもう一度開けます。

## 手順 2: アダプターに WinUSB を割り当てる {#winusb}

BlueCaster は、Windows に標準で入っている汎用 USB ドライバー WinUSB を通して、USB Bluetooth アダプターと直接通信します。**専用のアダプター**を用意することをおすすめします。そうすれば、内蔵 Bluetooth を Windows でこれまでどおり使えます。

1. **アダプター** 画面を開きます（セットアップの **ドライバーとファームウェア** では、**このアダプターを準備** が手順 2〜4 を行います）
2. アダプターの **ドライバー** には **元のドライバー**（または **ドライバーなし**）と表示されています。これは Windows またはメーカーが入れたドライバーで、WinUSB に置き換える対象です。**WinUSB ドライバーに置き換える** をクリックします
3. 確認の内容を読んで続行すると、Windows が管理者の許可（UAC）を求めます
4. ドライバーの表示が **WinUSB ドライバー** に変わります

アダプターが使用中のため Windows が WinUSB をすぐに読み込めなかったときは、BlueCaster がそのことを知らせ、ドライバーの行に **挿し直すか Windows を再起動** と表示されます。アダプターを抜いて挿し直してください。内蔵アダプターの場合は Windows を再起動します。それまでは接続に失敗し、ログに `failed to initialize WinUSB (error 50)` と記録されます。

{: .warning }
WinUSB を割り当てている間は、Windows の Bluetooth からそのアダプターが見えなくなります。そのアダプター経由で Windows にペアリングしたデバイスは、ドライバーを戻すまで使えません。キーボードやマウスなどの普段使う周辺機器には、内蔵 Bluetooth を使ってください。USB 接続の内蔵アダプター（多くのノート PC にある Realtek 製など）を BlueCaster に使うこともできます。ただしその場合、ドライバーを戻すまで **PC で Windows の Bluetooth がまったく使えなくなります**（Bluetooth の設定、マウス、キーボード、ほかのオーディオデバイス）。

同じ画面の **元のドライバーに戻す** で、アダプターを Windows に戻せます。Windows がドライバー（通常は Windows の Bluetooth ドライバー）を選び直し、アダプターを Windows の Bluetooth で使えるようになります。WinUSB を割り当て直すまで、BlueCaster はこのアダプターで配信できません。Windows が使う Bluetooth アダプターは一度に 1 つだけです。ほかのアダプターが使われている場合は、戻したあとに BlueCaster がそのことを知らせます。このアダプターを Windows で使うには、デバイス マネージャーでもう一方のアダプターを無効にし、このアダプターを挿し直してください。BlueCaster でペアリングし直したヘッドホンには新しいキーがあります。このアダプター経由で Windows にもペアリングされていたヘッドホンは、ドライバーを戻すときに新しいキーが Windows に渡されるので、ペアリングし直さずに Windows で接続できます。**制限:** 渡せるのはクラシックのペアリングだけで、LE のキーは渡せません。Windows が LE（LE Audio）で使うデバイスは、Windows でペアリングし直す必要があります（開発者モードでは LE のキーの受け渡しを試せます: **開発者 > デバッグ**）。

アンインストーラーでも同じことができます。アンインストール ウィザードのページの 1 つに、**元の Bluetooth ドライバーに戻す**（BlueCaster が WinUSB を割り当てたアダプターがあるとき。管理者の確認は 1 回だけ）と **ユーザーデータを削除する**（`%APPDATA%\BlueCaster` にある設定、コーデック、ペアリング、ファームウェアと、**対応しているコーデックのみ表示** などウィンドウが覚えている内容）があり、どちらも最初からオンです。WinUSB のアダプターが Zadig や v1 で設定したものだけの場合は、BlueCaster に記録がないため、1 つ目の項目はオフで表示されます。オンにすると、ドライバーは Windows が選びます。更新時とサイレント アンインストール（`/S`）では、WinUSB のまま残ります。同じページには、インストールされている場合に **VB-CABLE を削除する** と **Hi-Fi Cable を削除する** も表示されます。ほかのアプリも使っていることがあるため、最初はオフです。削除は VB-Audio のセットアップ画面を出さずに行われ、Windows が管理者の確認を求めます。そのあと Windows がハードウェアの変更をスキャンし、ケーブルはサウンドの一覧から消えます。まだ一覧に残っているときだけ、再起動を勧めます。

### Zadig を使う場合 {#zadig}

[Zadig](https://zadig.akeo.ie/) で入れた WinUSB ドライバーでも同じように動きます。

1. Zadig を開き、**Options > List All Devices** を選びます
2. ドロップダウンから USB Bluetooth アダプターを選びます
3. ターゲットドライバーに **WinUSB** を選び、**Replace Driver** をクリックします

### デバイス マネージャーで手動で行う {#device-manager}

アダプターが BlueCaster の一覧に表示されない、**アダプター** 画面のボタンが失敗する、同じ種類のほかのアダプターと動作が違う、といった場合は、Windows のデバイス マネージャー（**スタート** を右クリック > **デバイス マネージャー**）で同じ作業を手動で行えます。どちらの作業にも管理者権限が必要です。メニューの名前は Windows のバージョンによって少し異なることがあります。

**WinUSB ドライバーに置き換える**

1. アダプターを探します。通常は **Bluetooth** の下に製品名（例: 「TP-Link Bluetooth USB Adapter」）で表示されます。ドライバーの起動に失敗しているときは黄色の印が付いています。**表示 > デバイス (接続別)** にすると、PC 内蔵の Bluetooth と見分けやすくなります。内蔵のほうは、BlueCaster に使うのでなければ触らないでください
2. アダプターを右クリック > **ドライバーの更新** > **コンピューターを参照してドライバーを検索** > **コンピューター上の利用可能なドライバーの一覧から選択します**
3. デバイスの種類を聞かれたら **ユニバーサル シリアル バス デバイス** を選びます。**互換性のあるハードウェアを表示** のチェックを外し、製造元に **WinUsb デバイス**、モデルに **WinUsb デバイス** を選んで **次へ** をクリックし、警告を確認します
4. アダプターが **ユニバーサル シリアル バス デバイス** の下に **WinUsb デバイス** として表示されます。BlueCaster を再起動する（または **アダプター** 画面を開き直す）と、Zadig で設定した場合と同じように使えます

**元のドライバーに戻す**

1. **ユニバーサル シリアル バス デバイス** の下のアダプター（**WinUsb デバイス**）を右クリック > **デバイスのアンインストール** を選びます。WinUSB ドライバーを Zadig で入れた場合は、**このデバイスのドライバーを削除しようとしました** にもチェックを入れます。入れないと、Windows がまた Zadig のドライバーを選びます
2. アダプターを抜いて挿し直します（または **操作 > ハードウェア変更のスキャン**）。Windows が標準のドライバーを入れ、アダプターが **Bluetooth** の下に表示されます
3. そこで黄色の印が付いた場合（ドライバーの起動に失敗。例: コード 31）は、メーカーのドライバーがそのアダプターでは動きません。右クリック > **ドライバーの更新** > **コンピューターを参照してドライバーを検索** > **コンピューター上の利用可能なドライバーの一覧から選択します** > **汎用 Bluetooth アダプター** を選んでください。BlueCaster で使う場合は、上の手順で WinUSB を割り当て直します

## 手順 3: ヘッドホンを探す {#headphones}

**デバイスを検索**（**オーディオデバイス** 画面）は、USB アダプターを使って近くのデバイスを 30 秒間検索し、応答した順に一覧表示します。セットアップでは検索が自動で始まり、デバイスが接続されるか（**デバイスを追加** でそのデバイスを切断すると、検索を再開します）、**検索を停止** を押すか、セットアップを閉じるまで続きます。先にヘッドホンをペアリングモードにしてください。以前 BlueCaster でペアリングしたデバイスには **ペアリング済み** と表示されます。

検索で見つからないときは、**手動入力:** に Bluetooth アドレスを入力して **使う** をクリックします。入力または貼り付けたアドレスは、その場で整形されます。`AA:BB:CC:DD:EE:FF`、`aa-bb-cc-dd-ee-ff`、`AABBCCDDEEFF`、`AA BB CC DD EE FF` はどれも `AA:BB:CC:DD:EE:FF` になります。

WinUSB を割り当てる前に Windows がこのアダプター経由でペアリングしたヘッドホンは、そのペアリングを引き継げます。**Windows のペアリングを取り込む**（セットアップのデバイスの手順で、該当するデバイスがあるときに表示）を使うと、該当するデバイスがすべてチェックされた状態で一覧表示され、チェックしたデバイスのペアリングを取り込みます。取り込んだデバイスは、ペアリングモードにしなくても接続できます。Windows が管理者の許可を求めます。こうしたデバイスはふつうペアリングモードではないため、検索には表示されません。検索に表示された場合やアドレスを入力した場合は、**接続** や **追加** を押すと、Windows がペアリングしたデバイスであることを先に警告します。**このまま追加** を押すと、新しいデバイスとしてペアリングし直します。

**Windows 設定から確認**（ヘッドホンを PC 内蔵の Bluetooth とペアリングしている場合）:
1. **設定 > Bluetooth とデバイス** を開きます
2. オーディオデバイスをクリックします
3. **プロパティ** をクリックします
4. Bluetooth アドレスが表示されます（形式: `AA:BB:CC:DD:EE:FF`）

**コマンドラインから確認**（先に BlueCaster を終了してください。トレイ > **終了**）:
```
bluecaster-core.exe --cli --scan
```

ヘッドホンは、コーデック（**コーデック** 画面）が **自動**、出力ソース（**オーディオデバイス** 画面）がシステムの音の状態で始まります。この初期設定で最も良い音になります。そのほかの機能は[使い方](usage)をご覧ください。

## ファームウェア（Realtek アダプター） {#firmware}

Realtek ベースの USB Bluetooth アダプター（TP-Link UB500、RTL8761BU ドングルなど）は、動作に専用のファームウェアが必要です。CSR のアダプターはファームウェアが不要です。Intel、MediaTek MT79xx、Qualcomm、Broadcom のアダプターは、それぞれ専用のファームウェアファイルが必要になることがあります。[推奨アダプター](#adapters)を参照してください。

### アプリでの案内（ガイド付きダウンロード）

**アダプター** 画面（とセットアップの **ドライバーとファームウェア**）に、アダプターのファームウェアの状態が表示されます。**ファームウェアOK**、**Realtek のファイルは不要**（BlueCaster が認識できないアダプターで、チップを **Realtek 以外** にした場合）、または必要なファイル名付きの **ファームウェアが見つかりません** のいずれかです。**ダウンロードページを開く** ボタンでブラウザーに [linux-firmware/rtl_bt](https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git/tree/rtl_bt) ページを開き、**ファームウェアフォルダーを開く** で保存先のフォルダーを開きます。必要な `.bin` ファイルをダウンロードし、ファームウェアフォルダーに置いてください。

ほかのメーカーのアダプターには **Bluetooth チップ** の選択肢がなく、代わりにファームウェアの入手元がタグで表示されます。**MediaTek のドライバーから** または **Qualcomm のドライバーから**（メーカーの Windows ドライバーから読み込みます。このドライバーは WinUSB に切り替えたあともインストールされたままです）、**Wi-Fi ドライバーから**（Marvell。Wi-Fi はオンのままにしてください）、**ファームウェアフォルダーから**（Intel。**ダウンロードページを開く**、**ファームウェアフォルダーを開く**、**セットアップガイド** 付き）、**任意**（Broadcom の `.hcd`）、**不要**（CSR、Barrot、Actions）のいずれかです。BlueCaster が WinUSB 経由でファームウェアを読み込むと、タグは **読み込み済み** に変わります。読み込みに失敗したときは **読み込めませんでした** になり、**ダウンロードページを開く**、**ファームウェアフォルダーを開く** と、ファームウェアの入手元を示す行が表示されます。

RTL8761B のアダプター（TP-Link UB500 など）は、PC に Realtek の Windows ドライバーがインストールされていれば、ダウンロードは不要です。その場合、BlueCaster はそのドライバーのファームウェアを使います。このファームウェアは、アダプターを WinUSB に切り替えたあとも PC に残ります。Linux 用など別のファームウェアを読み込むには、**アダプター** 画面でアダプターのファームウェア欄にある **カスタムファームウェアを使う** を選びます。BlueCaster はファームウェアフォルダーのファイルを読み込むようになります。**ドライバーのファームウェアを使う** で元に戻せます。

**Bluetooth チップ** の一覧にあるチップなら、**ファームウェアをダウンロード** でこの作業を自動で行えます。確認すると、BlueCaster が linux-firmware（kernel.org）からファイルをダウンロードし、それぞれの SHA-256 を照合してからファームウェアフォルダーに保存します。linux-firmware にそのチップの config ファイルがない場合は空の `_config.bin` を保存し、チップは自身の設定を使います。ファイルは BlueCaster には含まれておらず、ボタンを押したときにだけダウンロードされます。

BlueCaster はアダプターのチップセットを検出し、必要なファームウェアファイルを表示します。

ファームウェアがなくても、Realtek のアダプターは ROM のコードで起動して応答するので、一見正常に見えます。しかし接続やストリーミングに失敗し、BlueCaster はファームウェアが読み込まれていないと表示します。また、以前のセッションで書き込んだファームウェアはアダプターの電源が切れるまで残ります。そのため、ファイルを削除しても、PC を再起動するかアダプターを抜くまでは動き続けることがあります。

### Bluetooth チップの設定

**アダプター** 画面の **Bluetooth チップ** の一覧では、BlueCaster がアダプターに Realtek の初期化（ファームウェアの書き込み）を行うかどうかを決めます。

| 選択肢 | 意味 |
|:-------|:-----|
| **自動**（既定） | BlueCaster の起動ごとに、検出したアダプターから判定します。既知の Realtek アダプターにはそのチップを使い、それ以外のアダプターには Realtek の初期化を行いません |
| **Realtek 以外** | Realtek の初期化を行いません。Intel、Broadcom、CSR などのアダプターを自動で認識できないときに選びます |
| **RTL8761BU**、**RTL8822CU** など | その Realtek チップとして扱います。自動で認識できない Realtek ベースのアダプター（独自の VID:PID を持つ OEM 製品）に必要です。そのチップの `.bin` ファイルがファームウェアフォルダーにあるかどうかが、状態欄に表示されます |
| **Custom** | ファームウェアフォルダーの `custom_fw.bin` と `custom_config.bin` を使います |

Realtek 以外のアダプターに Realtek のチップや Custom を選ばないでください。BlueCaster が Realtek のファームウェアを書き込もうとして、アダプターが起動しなくなることがあります。

### 手動ダウンロード

1. [linux-firmware/rtl_bt](https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git/tree/rtl_bt) から、チップセット用のファームウェアと config の `.bin` ファイルをダウンロードします（例: `rtl8761bu_fw.bin` と `rtl8761bu_config.bin`）
2. 両方のファイルを BlueCaster のファームウェアフォルダー（`%APPDATA%\BlueCaster\firmware`。**ファームウェアフォルダーを開く** でも開けます）に置きます

{: .note }
これらのファームウェアファイルは、linux-firmware プロジェクトで配布されている Realtek 独自のバイナリで、このリポジトリには含まれていません。再配布の条件は [WHENCE](https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git/tree/WHENCE) を参照してください。

## 推奨アダプター {#adapters}

BlueCaster で実際に使われたアダプターとヘッドホンは、コーデックや報告とあわせて[検証済みの機器](hardware)に載っています。

| チップセット | 製品例 | 備考 |
|:-------------|:-------|:-----|
| Realtek | TP-Link UB500、RTL8761BU | Realtek の Windows ドライバーがインストールされていれば、そのファームウェアを使用。なければファームウェアのダウンロードが必要（上記を参照）。最も検証済み |
| Realtek | RTL8852BD（`0BDA:B853`）、RTL8852BT、RTL8922A | BlueCaster は Realtek の Windows 用 Bluetooth ドライバーからファームウェア（例: `rtl8852bd_mp_chip_new.dat`）を読み込むので、そのドライバーはアンインストールしないでください。または、ログに示されたファイルをファームウェアフォルダーに置いてください。実機では未検証 |
| CSR | CSR8510 汎用ドングル | 挿すだけで動作。ファームウェア不要 |
| Barrot | Bluetooth 5.4 / 6.0 ドングル（`33FA:0010`、`33FA:0012`） | ROM のファームウェアで動作し、ファームウェアは不要。ユーザーからの報告は今のところ 1 件 |
| Marvell | Microsoft Surface Pro / Surface Book 内蔵（88W8897） | ファームウェアファイルは不要。Wi-Fi ドライバーが Bluetooth のファームウェアも読み込むので、Wi-Fi はオンのままにしてください。実機では未検証 |
| Actions | ATS2851 ドングル（`10D7:B012`） | ROM のファームウェアで動作し、ファームウェアは不要。このアダプターは対応していないコマンドも一覧に挙げるため、BlueCaster がそれらを隠します。実機では未検証 |
| Broadcom | ASUS BT400 (BCM20702)、そのほかの BCM20702 / BCM20703 / BCM43142 搭載ドングルやノート PC 内蔵モジュール | Bluetooth のクラス `E0/01/01` ではなくベンダークラス `FF/01/01` を名乗るアダプター（BCM20702 の OEM ドングル）も検出します。ROM のファームウェアで動作します。Broadcom の Windows 用 Bluetooth ドライバーが入っていれば、BlueCaster が起動時にそのドライバーのパッチを書き込みます。ファームウェアフォルダーに PatchRAM の `.hcd`（例: `BCM20702A1-0b05-17cb.hcd`）があれば、ドライバーのパッチの代わりにそのファイルを使います。ドライバーのパッチの書き込みに失敗したときは、アダプターを抜いて挿し直すよう BlueCaster が案内します。以後、BlueCaster はそのアダプターにパッチを書き込みません。ドライバーのパッチは実機では未検証 |
| Intel | Intel 7260 / 3160 / 7265 / 3165 / 3168 / 8260 / 8265 / 9260 / AX200 / AX201 / AX210 / AX211 | ブートローダーモード（コールドブートの後など）では、linux-firmware の `intel/` にある対応する `ibt-*.sfi` と `ibt-*.ddc` をファームウェアフォルダーに置く必要があります。必要なファイル名はログに出ます（例: `ibt-0180-0041.sfi`）。7260 / 3160 / 7265 / 3165 / 3168 は ROM で動作し、ファイルは不要です。同じフォルダーに対応する `ibt-hw-*.bseq` パッチがあれば、それを適用します |
| MediaTek | MT7925、MT7927、MT7922、MT7921、MT7902（AMD RZ717、RZ738、RZ616、RZ608 などの Wi-Fi カード） | チップごとの `BT_RAM_CODE_MT*_hdr.bin`（例: `BT_RAM_CODE_MT7925_1_1_hdr.bin`）が必要です。MediaTek の Windows 用 Bluetooth ドライバーが入っていれば、BlueCaster がそこから読み込みます。入っていなければ、linux-firmware の `mediatek/` にあるファイルをファームウェアフォルダーに置いてください。必要なファイル名はログに出ます。MT7927 は実機では未検証 |
| Qualcomm | QCA61x4、QCA9377（ROME）、WCN6855（FastConnect 6900）、WCN785x（FastConnect 7800） | チップの rampatch と NVM（例: `AthrBT_0x00000302.dfu` と `ramps_0x00000302_48.dfu`）が必要です。Qualcomm の Windows 用 Bluetooth ドライバーが入っていれば、BlueCaster がそこから読み込みます。入っていなければ、linux-firmware の `qca/` にあるファイル（`rampatch_usb_*.bin`、`nvm_usb_*.bin`）をファームウェアフォルダーに置いてください。必要なファイル名はログに出ます。実機では未検証 |
| MediaTek | MT7663 | チップのパッチファイル（例: `mt7663_patch_e2_hdr.bin`）が必要です。MediaTek の Windows 用 Bluetooth ドライバーが入っていれば、BlueCaster がそこから読み込みます。入っていなければ、このファイルをファームウェアフォルダーに置いてください。必要なファイル名はログに出ます。実機では未検証 |
| Qualcomm Atheros | AR3012 などの AR30xx チップ（古いノート PC の Bluetooth 4.0） | チップのパッチファイルと設定ファイル（例: `AthrBT_0x31010000.dfu` と `ramps_0x31010000_40.dfu`）が必要です。Qualcomm Atheros の Windows 用 Bluetooth ドライバーが入っていれば、BlueCaster がそこから読み込みます。入っていなければ、これらのファイルをファームウェアフォルダーに置いてください。必要なファイル名はログに出ます。実機では未検証 |
| MediaTek、Qualcomm | 古い MediaTek チップ（MT7630、MT7650 など）、ほかの Qualcomm チップ（QCA6290） | 未対応。BlueCaster にないファームウェアローダーが必要です（[対応の追加に協力する](chip-support)） |

LDAC のような高ビットレートのコーデックには、Bluetooth 5.0 以上の USB アダプターが一般に適しています。

複数のアダプターに WinUSB を割り当てていると、BlueCaster は最初に見つけたアダプターを使います。**アダプター** 画面で別のアダプターのカードにある **このアダプターを使う** を押すと、そのアダプターを使います。使用中のアダプターには **使用中** と表示されます。
